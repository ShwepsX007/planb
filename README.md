# PlanB — торговый бот на коррекции Фибоначчи (Gate.io) с веб-панелью

Бот ищет движения цены из нескольких свечей в одну сторону, растягивает по ним сетку
Фибоначчи, входит в сторону коррекции и ведёт позицию до заданного уровня коррекции,
усредняясь по рынку при движении против позиции. Управление — через веб-панель:
настройки, API-ключи, график со сеткой Фибо и сделками, журнал, статистика, бэктест.

Реализация полностью соответствует логике со скриншотов из репозитория:

* сетка растягивается от **минимума** (0 %) до **максимума** (100 %) движения;
* цель — уровень коррекции (**«цель»**, по умолчанию 50 % = середина сетки);
* при обновлении минимума сетка и цель **опускаются ближе к средней точке входа**;
* когда профит от средней точки входа до цели падает до «минимального % профита»,
  открывается **дополнительная позиция** (1-я и 2-я — базовым объёмом, 3-я — ×2,
  4-я — ×2 от 3-й и т. д.), средняя цена входа смещается ниже цели;
* при достижении целью цены весь цикл закрывается в профит, бот ждёт новый сигнал;
* работа продолжается до достижения **общего профита**, после чего бот останавливается.

## Как работает стратегия

Обозначения: `H` — максимум импульса, `L` — минимум импульса (обновляется), `goal` — цель
по Фибоначчи в %, `min_profit` — минимальный профит в %.

1. **Сигнал.** Бот берёт последние `candles_count` закрытых свечей. Если все они одного
   направления (по умолчанию: тело свечи вниз → ищем коррекцию вверх), то
   `H = max(high)`, `L = min(low)` этих свечей, а размер движения
   `move = (H − L) / L × 100 %` должен быть не меньше `min_move_pct`.
   Иначе сигнал игнорируется (причина видна в панели в строке «Последняя проверка»).
2. **Сетка Фибо.** Уровень считается как `price(k%) = L + k/100 × (H − L)`
   (0 % — минимум, 100 % — максимум, 1.618 — расширение).
3. **Вход №1.** На закрытии последней свечи импульса по рынку объёмом `base_volume_usd`.
   Вход разрешён, только если расстояние от цены входа до цели даёт не меньше
   `min_profit_pct` (иначе сигнал пропускается).
4. **Ведение.** Каждая новая свеча, пробившая минимум, растягивает сетку: цель
   `target = L_new + goal/100 × (H − L_new)` опускается вслед за ценой ближе к средней
   точке входа. Средняя цена входа — средневзвешенная по объёму:
   `avg = Σ(price_i × qty_i) / Σ(qty_i)`.
5. **Долив.** Когда `(target / avg − 1) × 100 % ≤ min_profit_pct` (профит от средней до
   цели сжался до минимума) и цена обновила экстремум — открывается следующая позиция
   по рынку. Объёмы: `base, base, base×mult, base×mult², …` начиная с позиции
   `multiplier_start_position` (по умолчанию 3-й: 10, 10, 20, 40, 80, 160 $).
   После долива средняя входа опускается ниже цели — и цикл снова становится прибыльным.
6. **Выход.** Как только цена достигает цели и профит от средней ≥ `min_profit_pct`
   (либо достигнут лимит `max_positions` и есть хоть минимальная прибыль) — весь цикл
   закрывается по рынку. Дальше бот ищет новый сигнал.
7. **Общий стоп.** Реализованный профит всех циклов суммируется; при достижении
   `total_profit_target_usd` бот останавливается и пишет об этом в журнал.
8. **Аварийный стоп.** Если задан `cycle_stop_loss_pct > 0`, при движении против средней
   входа на этот процент относительно позиции цикл закрывается в убыток и бот
   останавливается (по умолчанию выключено — стратегия является мартингейлом).

Выход исполняется рыночным ордером: бот проверяет цену каждые `poll_interval_sec` секунд
и на закрытии каждой свечи, поэтому фактическая цена выхода совпадает с целью или лучше
неё (при гэпе — по цене открытия свечи). Закрывается всегда вся позиция цикла, в LIVE-режиме
используется `reduceOnly`, чтобы случайно не перевернуть позицию.

Точные условия входа/долива/выхода (для проверки в коде):

```
entry:  move ≥ min_move  AND  price < target  AND  (target/price − 1)×100 ≥ min_profit
add:    positions < max_positions AND (target/avg − 1)×100 ≤ min_profit AND новый экстремум
exit:   price достиг target AND (target/avg − 1)×100 ≥ min_profit   (или лимит позиций)
stop:   realized_pnl ≥ total_profit_target_usd
```

Короткие позиции — зеркально: импульс вверх → шорт, цель — уровень коррекции вниз,
новый максимум поднимает цель к средней. На споте шорт недоступен, бот торгует только лонг.

> **Соотношение параметров.** Для первого входа нужно `move ≳ min_profit / (goal/100)`.
> Например, при цели 50 % и минимальном профите 1 % минимальное движение должно быть
> не меньше ~2 %. Слишком большие `min_profit_pct` при маленьком `min_move_pct` приведут
> к тому, что сигналы будут постоянно отбрасываться.

## Параметры

| Параметр | Что значит | По умолчанию |
|---|---|---|
| `timeframe` | таймфрейм свечей | `5m` |
| `candles_count` | количество свечей в одну сторону | `3` |
| `min_move_pct` | минимальное % движения цены для принятия в расчёт | `1.2` |
| `fib_goal_pct` | цель — уровень коррекции по Фибоначчи, % | `50` |
| `min_profit_pct` | минимальный % профита (порог долива и входа) | `0.5` |
| `base_volume_usd` | объём первой сделки, $ | `10` |
| `volume_multiplier` | множитель объёма следующих позиций | `2` |
| `multiplier_start_position` | с какой по счёту позиции умножать объём | `3` |
| `max_positions` | максимум позиций в одном цикле | `6` |
| `direction` | `both` / `long` / `short` | `both` |
| `total_profit_target_usd` | общий профит для остановки бота, $ (0 — без ограничения) | `50` |
| `cycle_stop_loss_pct` | аварийный стоп цикла, % (0 — выключен) | `0` |
| `market_type` | `futures` (USDT-M) или `spot` | `futures` |
| `trade_mode` | `paper` (виртуальные сделки) или `live` (реальные ордера) | `paper` |
| `data_source` | `gate` (реальные свечи) или `demo` (синтетический рынок) | `gate` |
| `fee_pct`, `slippage_pct` | комиссия и проскальзывание для расчётов | `0.05`, `0.02` |
| `leverage`, `margin_mode` | плечо и режим маржи для фьючерсов | `5`, `isolated` |
| `poll_interval_sec` | как часто опрашивать цену/свечи, сек | `3` |
| `demo_speed` | ускорение демо-рынка (1 = реальное время) | `1` |

Все параметры редактируются в панели на вкладке **Настройки** и сохраняются в SQLite.

## Быстрый старт

```bash
git clone <репозиторий> planb && cd planb
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# необязательно: закрыть панель логином/паролем
export PLANB_AUTH_USER=admin
export PLANB_AUTH_PASSWORD=смените-меня

python run.py            # http://<сервер>:8000
```

При первом старте создаётся база `data/planb.sqlite3` с настройками по умолчанию
(режим `paper`, реальные данные Gate.io). Если хочется посмотреть работу бота без
интернета и без ключей биржи — запустите с пресетом демо-данных:

```bash
PLANB_PRESET=demo python run.py       # синтетический рынок, ускоренный в 30 раз
```

Переменные окружения удобно держать в файле `.env` (шаблон — `.env.example`).

## Установка на сервер (VPS)

Ubuntu/Debian, systemd, без Docker:

```bash
# 1. пользователь и каталог
sudo useradd -r -m -d /opt/planb -s /usr/sbin/nologin planb
sudo mkdir -p /opt/planb && sudo chown planb:planb /opt/planb

# 2. код
sudo -u planb git clone <репозиторий> /opt/planb

# 3. окружение
sudo -u planb python3 -m venv /opt/planb/.venv
sudo -u planb /opt/planb/.venv/bin/pip install -r /opt/planb/requirements.txt

# 4. конфигурация
sudo -u planb cp /opt/planb/.env.example /opt/planb/.env
sudo -u planb nano /opt/planb/.env       # пароль панели, путь к базе

# 5. сервис
sudo cp /opt/planb/deploy/planb.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now planb
sudo systemctl status planb
journalctl -u planb -f
```

Открыть доступ к панели через nginx (пример):

```nginx
server {
    listen 443 ssl http2;
    server_name bot.example.com;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;      # нужно для WebSocket
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

**Обязательно закройте панель паролем** (`PLANB_AUTH_USER` / `PLANB_AUTH_PASSWORD`) —
через неё можно управлять торговлей. Дополнительно ограничьте доступ по IP
в файрволе или средствами nginx.

### Пошаговая установка на ваш сервер (пример: `/root/planb`, порт 8015)

Ниже — вариант установки, когда на сервере уже работают другие проекты. Бот займёт
**только** свой каталог `/root/planb`, свой systemd-юнит `planb.service` и **один порт**.
Nginx, чужие юниты, порты и базы не затрагиваются.

```bash
# 1. Подключаемся к серверу
ssh root@78.17.66.215

# 2. Смотрим, какие порты уже заняты другими проектами (скрипт сделает это и сам)
ss -ltnp

# 3. Забираем код (публичный репозиторий — доступы не нужны)
git clone --branch arena/00ac38c1-planb https://github.com/ShwepsX007/planb.git /root/planb

# 4. Устанавливаем: venv, зависимости, .env, systemd-сервис, самопроверка
bash /root/planb/deploy/install.sh
```

Скрипт идемпотентный — его же используют для обновления. Всё, что можно настроить:

```bash
PLANB_PORT=8015 \                      # порт панели (по умолчанию 8015)
PLANB_AUTH_USER=admin \                # логин в панель
PLANB_AUTH_PASSWORD='свой-пароль' \    # пароль (если не задать — сгенерируется и покажется)
PLANB_DIR=/root/planb \                # каталог установки
PLANB_PRESET=demo \                    # demo — синтетический рынок (без ключей биржи),
                                       # пусто — сразу реальные данные Gate.io
PLANB_AUTOSTART=1 \                    # поднимать бота после перезагрузки сервера
PLANB_OPEN_FIREWALL=1 \                # добавить правило в ufw/firewalld автоматически
bash /root/planb/deploy/install.sh
```

Что именно делает установщик:

| Шаг | Действие |
|---|---|
| 1 | проверяет, свободен ли порт; если занят чужим процессом — останавливается и показывает, кто держит порт |
| 2 | ставит системные пакеты (python3 3.9+, venv, pip, git, curl), при необходимости python3.11 |
| 3 | раскладывает код в `/root/planb` (при обновлении — `git fetch` + сброс на ветку с кодом) |
| 4 | создаёт изолированное окружение `/root/planb/.venv` и ставит зависимости |
| 5 | пишет `/root/planb/.env` (права `600`) со случайным паролем панели, портом 8015 и путём к базе |
| 6 | создаёт `/etc/systemd/system/planb.service` (`Restart=always`, автозапуск при загрузке) |
| 7 | запускает сервис и ждёт ответа `/api/health`; выводит адрес, логин и пароль |
| 8 | подсказывает команду для файрвола, если ufw/firewalld активен |

Проверка после установки:

```bash
systemctl status planb                 # активен, автозапуск включён
ss -ltnp | grep 8015                   # слушает только наш порт
journalctl -u planb -n 30 --no-pager   # журнал сервиса
curl -u admin:ПАРОЛЬ http://127.0.0.1:8015/api/health
# из браузера: http://78.17.66.215:8015/
```

Не забудьте открыть порт 8015 в файрволе (`ufw allow 8015/tcp`) и в Security Group облака.
Дальше — вкладка **Настройки** в панели: API-ключи Gate.io, «Проверить подключение»,
при желании `trade_mode = live`; затем кнопка **Старт**.

**Перезагрузка и падения.** Сервис включён в автозагрузку (`systemctl enable`), при
аварийном выходе systemd поднимает его через 5 секунд (`Restart=always`). Бот помнит,
работал ли он: если вы нажимали «Старт» — после перезагрузки он вернётся в работу и
продолжит вести открытый цикл; если нажимали «Стоп» — останется остановленным. Свежая
установка ничего не торгует, пока вы не нажмёте «Старт». Отключить это поведение можно
переменной `PLANB_AUTOSTART=0` в `/root/planb/.env`.

**Обновление версии:**

```bash
cd /root/planb && git pull && .venv/bin/pip install -r requirements.txt && systemctl restart planb
# или просто: bash /root/planb/deploy/install.sh     (сделает то же самое)
```

**Смена порта:** `PLANB_PORT=8020 bash /root/planb/deploy/install.sh` (перепишет `.env` и юнит,
перезапустит сервис; база и настройки сохранятся).

**Удаление:** `bash /root/planb/deploy/uninstall.sh` (убирает юнит и останавливает сервис;
каталог с базой остаётся — удалите вручную, если нужно).

**Проверка изолированности от других проектов:**

```bash
systemctl list-units --type=service | grep planb    # наш единственный юнит
ss -ltnp | grep 8015                                # наш единственный порт
ls -la /root/planb                                  # всё внутри этого каталога
```

Если позже понадобится домен и HTTPS, панель работает и за nginx (в том числе
**за префиксом** — все запросы в интерфейсе относительные):

```nginx
# вариант 1: отдельный поддомен
server {
    listen 443 ssl http2;
    server_name planb.example.com;
    location / {
        proxy_pass http://127.0.0.1:8015;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;   # WebSocket (живое обновление панели)
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
    }
}

# вариант 2: путь на уже используемом домене (важно: префикс со слешем на конце)
location /planb/ {
    proxy_pass http://127.0.0.1:8015/;            # именно со слешем в конце
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
}
```

**Адрес панели — корень без пути.** Панель: `http://СЕРВЕР:8015/`.
Адрес `http://СЕРВЕР:8015/api/health` — служебный (для мониторинга и healthcheck): в нём
браузер покажет JSON вида `{"ok":true,"status":"running"}`. Если открыть его в браузере,
страница сама предложит ссылку «Открыть панель PlanB».

**Пароль панели** задаётся и меняется без правки файлов:

```bash
bash /root/planb/deploy/set-auth.sh --show            # посмотреть адрес, логин и пароль
bash /root/planb/deploy/set-auth.sh 'novy-parol123'   # сменить пароль (латиница — надёжнее)
bash /root/planb/deploy/set-auth.sh --off             # отключить пароль (панель открыта всем!)
bash /root/planb/deploy/set-auth.sh --user operator 'parol'   # сменить и логин
```

Скрипт правит только строки `PLANB_AUTH_*` в `.env` (делая резервную копию), перезапускает
сервис и сразу проверяет панель: страница, статика, API, вход без пароля и с неверным паролем.

**Если бот работает, а входов нет.** Это нормальное поведение, если рынок не даёт движения
больше порога: стратегия ждёт `candles_count` свечей в одну сторону и движение не меньше
`min_move_pct`. Панель это объясняет цифрами: в блоке «Что делает бот» видны последняя
обработанная свеча, сколько свечей обработано за сессию и строки сканера сигналов —
сколько входов было бы за последние свечи, какими были движения (медиана/максимум) и какой
порог. Если сигналов ноль — сверху появляется подсказка с предложенным порогом и кнопкой
**«Проверить сигналы заново»** (тот же расчёт по свежей истории, до 1500 свечей).
Через API: `GET /api/signals/scan?refresh=1&limit=1000`.

Если за историю не было ни одного входа, бот пишет это в журнал сам — один раз на настройки,
без спама каждым циклом:

```
warn Входов не было: за 299 окон истории (≈5 ч, 301 свечей 1m) движения в окне настроек были
     от 0.351% (медиана) до 1.259% (максимум), а порог «Минимальное движение цены» — 3.0%.
     Похоже, порог выше рынка: попробуйте 0.7% и «Минимальный профит» не больше 0.35%
     (сейчас 0.15%), либо таймфрейм крупнее.
```

Если данные с биржи вообще не приходят (последний ответ больше 3 минут назад), панель говорит
именно об этом, а не о порогах: сначала проверьте связь.

Ориентиры для BTC (движение трёх свечей в одну сторону):

| Таймфрейм | Типичное движение 3 свечей | Разумный `min_move_pct` |
|---|---|---|
| 1m | 0.05–0.25 % | 0.15–0.3 % |
| 5m | 0.2–0.8 % | 0.5–0.8 % |
| 15m | 0.4–1.5 % | 0.8–1.5 % |

Помните: вход возможен, только если профит от входа до уровня цели не меньше
`min_profit_pct` (при цели 50 % сетки это примерно половина движения). Поэтому
при `min_move_pct = 0.6 %` и цели 50 % следует ставить `min_profit_pct` не больше 0.25 %.

**Бот после установки остановлен** — это нормально: свежая установка ничего не торгует, пока
вы не нажмёте «Старт». По умолчанию включён демо-рынок и виртуальные сделки (paper), ключи
биржи не нужны. В панели на дашборде об этом пишет подсказка сверху.

**Если в браузере «белый экран».** На сервере есть готовый диагностический скрипт —
он проверяет службу, порт, страницу, статику, доступ из интернета и nginx:

```bash
bash /root/planb/deploy/check.sh
```

Что чаще всего бывает и как это выглядит:

| Симптом | Причина | Решение |
|---|---|---|
| Страница грузится вечно, пусто; `/api/health` по внешнему адресу не отвечает | порт 8015 закрыт файрволом или Security Group облака | открыть TCP 8015 (`ufw allow 8015/tcp`, правило Ingress в панели провайдера) **или** опубликовать панель через nginx: `bash /root/planb/deploy/setup-nginx.sh` |
| Белый экран, в логе сервиса ошибка 500 | пароль с не-ASCII символами (например кириллица) — так было в версии до 16.10, сейчас исправлено | обновиться: `bash /root/planb/deploy/install.sh` (или задать пароль из латиницы) |
| Браузер показывает окно с логином/паролем, после ввода снова пусто | неверный пароль или браузер подставляет старый сохранённый | `bash /root/planb/deploy/set-auth.sh --show` покажет актуальные логин и пароль; открывайте панель в приватном окне |
| Служба `planb` активна, но страница не открывается, порт 8015 «никто не слушает» | бот стартовал медленно (сеть/биржа) или падал при запуске: uvicorn открывает порт только после стартовых обработчиков | обновиться (`git pull && systemctl restart planb`): панель теперь поднимается сразу, а бот догружается в фоне; если порт всё ещё закрыт — `bash deploy/check.sh` покажет журнал службы, счётчик перезапусков и самопроверку кода |
| В браузере видно `{"ok":true,...}` | открыт служебный адрес `/api/health` | панель — по адресу без пути: `http://СЕРВЕР:8015/` |
| Адрес открывается, но по `https://` — «не удалось установить соединение» | панель работает по HTTP, а браузер подставляет HTTPS | набрать адрес явно: `http://IP:8015/` |
| В обычном окне пусто/старая версия, а в приватном всё работает | браузер держит старую страницу в кеше (и/или подставляет сохранённый пароль) | обновить страницу с Ctrl+F5 (Cmd+Shift+R на macOS) или очистить кеш для этого адреса. Начиная с этой версии панель отдаёт `Cache-Control: no-store`, так что повторно это не залипнет |
| Пустая страница после настройки nginx | несовпадение префикса (`/planb` и `/planb/`) | использовать конфиг из `deploy/setup-nginx.sh` — он делает редирект `/planb` → `/planb/` |
| Бот показывает цены, которых нет на бирже / «данные: synthetic» | выбран синтетический источник (выдуманные свечи) | «Настройки» → «Источник данных» → `Gate.io` → «Сохранить»; проверить связь кнопкой «Проверить подключение» |

**Публикация панели через nginx.** Если порт наружу не открывается или нужен домен с HTTPS:

```bash
# вариант 1: путь на уже работающем сайте -> http://ДОМЕН/planb/
bash /root/planb/deploy/setup-nginx.sh

# вариант 2: отдельный поддомен -> http://planb.example.com/planb/
DOMAIN=planb.example.com bash /root/planb/deploy/setup-nginx.sh
# затем HTTPS:  certbot --nginx -d planb.example.com
```

Скрипт правит **один** файл конфигурации, делает резервную копию и откатывает изменения,
если `nginx -t` не прошёл, — чужие проекты не пострадают. Панель полностью работает за
префиксом: пути в интерфейсе относительные, WebSocket подключается через тот же префикс.

**Смена пароля панели.**

```bash
PLANB_AUTH_PASSWORD='novy-parol' bash /root/planb/deploy/install.sh
# скрипт перепишет .env и перезапустит сервис; код, база и настройки сохранятся
```

## API-ключи Gate.io

1. Gate.io → **API Management → API v4 Keys → Create API Key**.
2. Права: для фьючерсов — `Futures: Trade` (+ `Read`/`Account` для баланса и позиций),
   для спота — `Spot: Trade`. **Не включайте** `Withdraw` и передачу ключа третьим лицам.
3. Желательно указать IP-адрес сервера в ограничениях ключа.
4. Вставьте ключ и секрет в панели на вкладке **Настройки** и нажмите
   «Проверить подключение», затем выберите `market_type`, плечо и режим маржи.
5. Для первых запусков оставьте `trade_mode = paper` — бот торгует виртуально на реальных
   ценах, а вы видите все сделки, средние входы и профит. После проверки стратегии
   и настройки параметров переключите на `live`.

## Веб-панель

- **Панель** — текущее состояние: общий профит и прогресс до цели, средняя входа,
  цель, профит до цели, количество позиций, следующий долив, таблица позиций цикла,
  «что делает бот» (последняя проверка условий).
- **График** — свечи, полная сетка Фибоначчи (0 … 1.618), белая линия «цель»,
  синяя линия «средняя входа», маркеры входов с номерами позиций (`1`, `2`, `3 x2`, …)
  и закрытий циклов.
- **Позиции** — открытые позиции и план объёмов по позициям.
- **Циклы и сделки** — вся история из базы, экспорт в CSV.
- **Бэктест** — прогон стратегии на реальной истории: свечи скачиваются прямо с Gate.io
  (или загружаются своим CSV), метрики, кривая доходности, список циклов.
- **Настройки** — все параметры, ключи, проверка подключения.
- **Журнал** — события бота в реальном времени (входы, доливы, закрытия, ошибки).

Кнопки: **Старт**, **Пауза** (новые сделки не открываются, цель по открытому циклу
отслеживается), **Стоп**, **Закрыть всё** (аварийное закрытие текущего цикла по рынку).

## Реальные данные и виртуальные сделки (важно)

В боте два независимых переключателя, и их часто путают:

| Настройка | Значение | Что это значит |
|---|---|---|
| **Источник данных** | `Gate.io` | свечи и цена берутся с настоящей биржи (публичный API, **API-ключи не нужны**) |
| **Источник данных** | `Синтетика` | выдуманный random-walk — только чтобы посмотреть панель без интернета |
| **Режим торговли** | `paper` | сделки **виртуальные**: бот считает прибыль, но ордера на биржу не отправляет |
| **Режим торговли** | `live` | реальные ордера (нужны API-ключи, есть риск потерять деньги) |

Значит «демо-режим» = **источник Gate.io + режим paper**: настоящий рынок, настоящие свечи,
виртуальные деньги. Именно так настроена свежая установка (`PLANB_PRESET=demo`).

* бот стартует и при небольшом числе сигналов: если рынок не даёт вход, панель так и пишет
  («нет активного цикла — ждём сигнал»), а не выдумывает сделки;
* в шапке панели всегда видно, откуда данные: зелёный бейдж **РЕАЛЬНЫЕ ДАННЫЕ GATE.IO**
  или фиолетовый **СИНТЕТИКА (ВЫДУМАННЫЕ СВЕЧИ)**;
* на дашборде в блоке «Что делает бот» видно время последней свечи, время последнего
  успешного запроса и текст ошибки, если связи с биржей нет;
* если биржа недоступна (нет интернета, гео-ограничение), бот **не подменяет данные**
  выдуманными молча — в панели появляется красная плашка с причиной и командой для проверки:
  `curl -s -m 10 https://api.gateio.ws/api/v4/spot/time`;
* кнопка **«Проверить подключение»** на вкладке «Настройки» работает и без ключей: она
  показывает цену, время последней свечи и задержку ответа биржи;
* бот отказывается включать реальную торговлю (`live`) на выдуманных свечах: такая
  комбинация отклоняется с объяснением — реальные деньги только на реальных данных.

Если установка шла с пресетом синтетики (`.env`: `PLANB_PRESET=synthetic`), её нужно
переключить: вкладка «Настройки» → «Источник данных» → `Gate.io` → «Сохранить».
Старые установки с пресетом `demo` (в котором раньше был выдуманный рынок) переводятся
на реальные свечи автоматически, и в журнале появляется запись об этом.

## Бэктест на реальной истории

**Ничего скачивать вручную не нужно.** Вкладка **Бэктест**:

1. задайте пару, рынок (фьючерсы/спот), таймфрейм и период — «последние N свечей»
   или «с даты по дату» (даты в **UTC**; понимаются также «31.01.2026 12:00»);
2. нажмите **«Скачать и запустить»** — сервер сам заберёт историю с Gate.io страницами
   по 1000 свечей, покажет ход загрузки и сразу прогонит стратегию на этих данных;
3. результат сохраняется в базу (`/api/backtests`) вместе с описанием данных: сколько
   свечей, за какой период, сколько пропусков.

Что можно скачать: любые пары Gate.io, таймфреймы от 1m до 1d. Для **спота** доступна
длинная история — наш предел 200 000 свечей за раз. У **фьючерсов** Gate.io отдаёт только
последние ~10 000 свечей на выбранном таймфрейме (`Candlestick too long ago. Maximum 10000
points recently are allowed`): панель об этом предупредит и сама возьмёт доступный отрезок.
Поэтому для длинных периодов на фьючерсах берите таймфрейм крупнее (10 000 свечей 4h — это
~4,5 года) либо тестируйте на споте. Скачанные свечи кладутся в `data/candles/*.csv`
и остаются на сервере — один и тот же период можно прогонять повторно с другими параметрами
(кнопка **«Запустить на выбранном файле»**).

### Откуда взять данные вручную (если захочется)

Обычно ничего скачивать не нужно — панель делает это сама. Но если хочется посмотреть
или сохранить свечи самому, вот прямые адреса публичного API Gate.io (ключи не нужны):

```bash
# спот: BTC/USDT, 5 минут, 1000 свечей (можно указать from/to — unix-время в секундах)
curl -s 'https://api.gateio.ws/api/v4/spot/candlesticks?currency_pair=BTC_USDT&interval=5m&limit=1000' | head -c 300

# фьючерсы USDT-M: до 2000 свечей за запрос, вглубь — только ~10 000 свечей
curl -s 'https://api.gateio.ws/api/v4/futures/usdt/candlesticks?contract=BTC_USDT&interval=5m&limit=1000' | head -c 300
```

Формат ответа — массив массивов `[время, объём, close, high, low, open, …]`; документация:
`https://www.gate.com/docs/developers/apiv4/en/`. Готовых «месячных архивов», как у Binance,
Gate не публикует — история отдаётся только через API.

**Архивы Binance (data.binance.vision).** Если нужна именно выгрузка архивом или период
поглубже, чем даёт Gate по фьючерсам, подойдут публичные архивы Binance — панель принимает
их **как есть, без распаковки** (ZIP с CSV внутри):

```bash
# месячный архив: все свечи BTCUSDT за месяц, интервал 5m
curl -LO 'https://data.binance.vision/data/spot/monthly/klines/BTCUSDT/5m/BTCUSDT-5m-2026-09.zip'
# или фьючерсы USD-M:  .../data/um/monthly/klines/BTCUSDT/5m/BTCUSDT-5m-2026-09.zip
```

Дальше: панель → «Бэктест» → блок «Или свои свечи» → выбрать этот ZIP → «Загрузить на сервер»
(можно и просто `scp` в `data/candles/`). Binance-выгрузки пишут время в микросекундах и
содержат 12 колонок — это поддерживается, лишние колонки игнорируются. Помните, что цены
Binance и Gate совпадают не идеально, но логика стратегии от этого не меняется.

**Свои данные (CSV или ZIP).** Если у вас есть файл свечей (выгрузка Gate.io, Binance,
TradingView, Excel), загрузите его прямо в панели: блок «Или свои свечи» → выбрать файл →
«Загрузить на сервер». Принимаются и **ZIP/GZIP-архивы с CSV внутри** — месячные выгрузки
распаковывать не нужно. Файл нормализуется и попадёт в `data/candles/` (оттуда его можно
скачать или удалить), и его можно прогонять сколько угодно раз. Лимит — 200 000 свечей,
дальше берутся последние (о чём панель сообщит). Формат — простой, заголовок не обязателен:

```csv
ts,open,high,low,close,volume
2026-01-01 00:00:00,60000,60100,59900,60050,12.5
2026-01-01 00:05:00,60050,60200,60000,60150,10
```

Понимаются: разделитель `,` или `;`, десятичная запятая (60000,5), время в секундах,
миллисекундах, **микросекундах** (так пишет Binance), ISO-дате с долями и таймзоной или
дате `31.01.2026 12:00`; заголовки `time/date/ts/open_time/время`, `open/high/low/close/volume/объём`
(выгрузки с 12 колонками тоже читаются), лишние колонки игнорируются, поломанные строки —
пропускаются со счётчиком. Можно и просто положить файл на сервер:

```bash
scp moysвечи.csv root@78.17.66.215:/root/planb/data/candles/
```

**Синтетика без интернета** — кнопка «Синтетика» (для проверки самой панели и расчётов
на выдуманном рынке).

Результат бэктеста: итоговый баланс, общий профит, число циклов, win rate, максимальная
просадка, максимум одновременно открытых позиций, комиссии, profit factor, кривая
доходности, таблица циклов и метки сделок на графике. Так можно подобрать таймфрейм,
порог движения, уровень цели и сетку объёмов **до** включения реальной торговли.

Пример из CLI:

```python
from app.config import BotSettings
from app.backtest import run_backtest
from app.feed import demo_candles

s = BotSettings(timeframe="5m", candles_count=3, min_move_pct=1.0,
                min_profit_pct=0.5, fib_goal_pct=50, max_positions=6)
# синтетика — быстро и без интернета
result = run_backtest(demo_candles(20000, seed=1, settings=s), s)
print(result["cycles"], result["total_pnl"], result["max_drawdown"], result["max_positions_used"])

# реальная история с биржи (то же самое делает вкладка «Бэктест» в панели)
import asyncio
from app.history import HistoryRequest, download_candles

req = HistoryRequest(symbol="BTC/USDT", market_type="futures", timeframe="5m",
                     date_from="2026-01-01", date_to="2026-02-01")
candles = asyncio.run(download_candles(s, req, progress=lambda n, t, m: print(m)))
print(run_backtest(candles, s)["cycles"])
```

## REST API и WebSocket

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/state` | полное состояние бота (то же, что идёт в WebSocket) |

| POST | `/api/backtest/job/{id}/cancel` | отменить загрузку/расчёт |
| GET/POST | `/api/backtest/files` | список своих CSV со свечами / загрузка нового (тело — текст CSV) |
| GET/DELETE | `/api/backtest/files/{name}` | скачать/удалить файл свечей |
| GET | `/api/backtests`, `/api/backtest/{id}` | список/результат бэктестов |
| WS | `/ws` | поток снапшотов состояния и логов (1 раз в секунду) |

бэктеста и API свечей (в том числе авторизация панели, разбор ZIP-архивов и
микросекундных меток Binance, предупреждение о лимите истории у фьючерсов, доставка закрытых свечей от биржи
(регрессия «бот молчит») и сканер сигналов).

Отдельно есть smoke-тест панели на jsdom (см. `tests/panel/README.md`) — он проверяет,
что интерфейс корректно отрисовывает состояние бота без браузера.

## Риски и важные предупреждения

* **Стратегия — мартингейл.** Усреднение с удвоением объёма даёт высокий процент
  прибыльных циклов, но редкий сильный тренд против позиции может съесть прибыль многих
  циклов. Обязательно ограничивайте `max_positions`, задавайте разумный
  `cycle_stop_loss_pct` для аварийного стопа и не держите на счёте больше, чем готовы
  потерять. Начинайте с `base_volume_usd`, при котором максимальный объём цикла
  (последняя позиция сетки) соответствует вашему допустимому риску.
* Проверяйте параметры на бэктесте и в `paper`-режиме — рынок и комиссии съедают часть
  математического преимущества.
* Официальный API биржи может быть недоступен из вашей страны (гео-ограничение Gate.io) —
  тогда бот напишет причину в панели и журнале, а работать будет только синтетический
  источник: реальные данные бот выдуманными не подменяет. Проверка: раздел 8 в
  `deploy/check.sh` или кнопка «Проверить подключение» на вкладке «Настройки».
* Проект не является инвестиционной рекомендацией. Торговля с плечом может привести
  к полной потере средств.
