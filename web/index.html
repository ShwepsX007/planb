Логика расчёта

1. Бот ищет движение целиком: —. Окно анализа — до — свечей таймфрейма 5m, движение должно быть не меньше —%. В swing число свечей считается автоматически; фиксированное N (3) нужно только для старого impulse-режима.

2. Растягивает сетку Фибоначчи по всему движению: 0% — конец движения (последний минимум при падении, последний максимум при росте), 100% — его начало (предыдущий противоположный экстремум). Для падения 0 внизу, для роста — 0 вверху. Вход — на коррекции, когда цена отошла от экстремума, но ещё не дошла до цели.

3. Цель — уровень —% сетки. Пока цена не дошла до цели, каждое обновление экстремума тянет сетку и цель ближе к средней точке входа.

4. Когда профит от средней входа до цели становится меньше —%, бот доливается: 1-я и 2-я сделки базовым объёмом, далее объём умножается на — — так средняя цена входа опускается ниже цели.

5. Когда цена достигает цели коррекции, все позиции закрываются, если профит от средней входа ≥ минимального. Если цена ушла дальше цели, бот фиксирует по фактической цене (лучше цели), а не ждёт откат. Долив, после которого профит до цели стал бы меньше минимума, не делается — иначе цикл «завис бы» без возможности закрыться в плюс.

5а. Долив делается на каждом новом экстремуме, пока профит до цели не станет не меньше минимального: даже если один долив не закрывает разрыв сразу, следующая позиция сдвигает среднюю ближе к цене. Пока экстремум не обновлён, бот пишет «нужен новый минимум».

6. Работа продолжается, пока общий профит не достигнет цели —$ (или пока вы не остановите бота).

План объёмов

Объёмы долей считаются по формуле: базовый объём для позиций 1..(N−1), далее каждый следующий объём умножается на множитель, начиная с указанной позиции.

1. Свечи с биржи Gate.io

Сервер сам берёт данные с Gate.io, ключи не нужны. Архив — официальные месячные файлы с 2023 года: любой период, годы истории, кешируется на сервере (повторный прогон — сразу). API — быстрый способ для последних ~10 000 свечей. Даты — в UTC.

2. Или свои свечи (CSV / ZIP-архив)

Подойдёт любой файл со свечами: CSV с колонками ts,open,high,low,close,volume (выгрузка Gate.io, TradingView, Excel) или ZIP/GZIP-архив с CSV внутри — например месячные выгрузки Binance с data.binance.vision: их можно не распаковывать. Понимаем разделитель «,» и «;», время секундами, миллисекундами, микросекундами или датой, лишние колонки игнорируем. Файл остаётся на сервере и годится для повторных прогонов.

Циклы бэктеста

Просадка в статистике рассчитана по close-to-close equity: realized + плавающий P/L, комиссии учтены. Неблагоприятный P/L цикла — максимальный наблюдавшийся плавающий убыток; процент — от суммарного объёма входов. Объём позиции здесь трактуется как номинал: плечо меняет требуемую маржу и доступность входов, но не P/L на тот же номинал. Для фьючерсов оценка маржи = номинал / плечо; при нехватке свободной маржи вход отклоняется. Не учитываются maintenance margin/funding. Equity ≤ 0 отмечается как «слив».

Настройки бота

API-ключи хранятся в локальной базе данных на сервере (data/planb.sqlite3), доступ к панели можно закрыть логином/паролем через переменные окружения PLANB_AUTH_USER и PLANB_AUTH_PASSWORD.

Ограничение по API-ключу

Создайте ключ в Gate.io: API Management → API v4 Keys. Для торговли на фьючерсах достаточно прав Futures – Trade (и Read для чтения баланса), для спота — Spot – Trade. Не включайте вывод средств (Withdraw) и передачу. По возможности ограничьте ключ вашим IP-адресом сервера.

Начните с режима paper (виртуальные сделки на реальных данных) — так вы увидите, как бот работает на ваших настройках, без риска.
